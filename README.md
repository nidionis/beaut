# beaut

A small cluster orchestrator for ARM/Linux nodes.

- **beaut-tool** (C, `src/`) — the control CLI: identity, scheduling view,
  encrypted logs, and the dispatch data it receives.
- **beaut-router** (C, `src/router.c`) — a front door: listens, forwards
  every connection to the orchestrator.
- **beaut** (bash, generated by `env.sh`) — the runtime: the `watch` loop
  that polls the log and dispatches tasks; plus `init`, `heartbeat`,
  `peers`, `pick`, `run`.
- **beaut-lib** (bash, generated by `env.sh`) — shared helpers sourced by
  every `beaut*` script.

The three shell scripts are the operational entry points:

| script        | what it does                                                        |
| ------------- | ------------------------------------------------------------------ |
| `install.sh`  | entry point: runs env.sh, installs binaries + systemd units, prints status |
| `env.sh`      | configures identity, CPU policy, systemd units, and generates the runtime scripts |
| `build.sh`    | detects the target arch, checks deps, compiles, runs the smoke test |

`src/` holds the C sources and is the single source of truth — the build
scripts compile them; they never regenerate them.

## Quick start (fresh node)

```sh
sudo ./install.sh orchestrator 10.0.0.1     # or: router | worker | client
```

The script installs the binaries, creates the `beaut` system user,
generates config and systemd units, and enables the heartbeat timer.

Useful subcommands:

```sh
sudo ./install.sh --status     # show unit status
sudo ./install.sh --uninstall # disable everything beaut installed
sudo ./install.sh --serve 8080 # serve the scripts themselves (for bootstrapping other nodes)
```

## Runtime commands

After install, `beaut` and `beaut-tool` are on the path:

```sh
beaut init                 # verify identity, show role
beaut heartbeat           # post one heartbeat line
beaut peers               # scheduler view
beaut pick                # best worker and the next one
beaut run <domain> <cmd> # post a task to the best worker
beaut watch               # dispatch loop (used by the service)
```

`beaut-tool` commands: `join`, `approve`, `auth`, `cores`, `role`,
`post`, `read`, `peers`, `pick`, `heartbeat`, `retain`, `encode`, `decode`.

## Configuration

All settings come from environment variables (defaults are sensible).
Some noteworthy ones:

- `BEAUT_PASSWORD` — password for the admin identity; `join`/`approve`
  provision `priv.tsv`.
- `BEAUT_STATE_DIR`, `BEAUT_ETC_DIR` — where encrypted logs and identity
  files live (`/var/lib/beaut`, `/etc/beaut` by default).
- `SALV_COEF` — scheduler split of online cores, e.g. `1/3`.
- `BEAUT_STALE_S` — heartbeat age after which a peer is dropped (`90`).
- `BEAUT_HEARTBEAT_S` — heartbeat interval (`30`).
- `BEAUT_POLL_S` — how often `watch` re-reads the log (`3`).
- `BEAUT_ALLOW_EXEC` / `BEAUT_EXEC_DOMAINS` — whether and where tasks may
  actually run.

The public config (`beaut.conf`) is group-readable; the secret config
holding the password is root-only.

## Security notes

- Identity data is Argon2id-keyed; logs are encrypted with
  XChaCha20-Poly1305 (libsodium).
- Only the `beaut` group may run `beaut*` commands without a password
  (sudoers is managed by `env.sh`).
- Files under `/var/lib/beaut` and `/etc/beaut` are owned by the `beaut`
  user and group.
